и выпуска/продления публичного сертификата на реальном адресе. Протокол локальных
проверок обновляется после фактического выполнения; наличие скрипта не означает успех.

## Воспроизводимая проверка на чистой VM

Используйте отдельные VM Ubuntu 24.04 и Debian 13 с публичным IPv4 и systemd.
Для расширенной матрицы повторите на остальных заявленных версиях ОС и arm64.
Разрешите входящие 80, 443, 2053/TCP в firewall провайдера. Скопируйте исходный проект
или опубликуйте архив через `scripts/pack-release.sh`. Не используйте рабочий VPN-сервер.

1. Запустите `sudo bash scripts/install.sh`. Убедитесь, что Docker отсутствует,
   установщик предлагает его установку и спрашивает порт с default 2053.
2. Откройте `https://IP:2053` с другой машины. Проверьте доверенную цепочку сертификата,
   IP SAN, отсутствие HTTP и фактические статусы обоих сервисов.
3. Сохраните учётные данные. Проверьте права файлов (`0600`, каталоги `0700`),
   отсутствие логина и пароля в `docker compose logs`.
4. Повторите установку, затем перезагрузите VM. Проверьте готовность, неизменность
   имени, bcrypt-хеша администратора, ключей и сохранённых портов.
5. Остановите Xray: `docker compose stop xray`. `/health/ready` должен вернуть 503,
   `/health/live` — 200. Запустите Xray и дождитесь восстановления 200 без перезапуска Go.
6. Убедитесь, что 10085 недоступен с другой машины, а 443 отвечает как VPN-listener.
7. В отдельной тестовой установке занять 443 командой `python3 -m http.server 443`:
   установщик должен выбрать 8443. Занять 2053 — должен отказать, не занимать другой
   порт панели молча. Занять оба VPN-порта — должен завершиться ошибкой.
8. Закрыть 80/TCP снаружи: `TLS_MODE=acme` должен завершиться ошибкой без ложного
   сообщения об успешной установке. `TLS_MODE=auto` должен предложить резервный HTTPS.
   При `NONINTERACTIVE=1` без `ALLOW_SELF_SIGNED=1` переход должен быть запрещён.
9. На машине без публичного IPv4 установщик должен отказать; `PUBLIC_IP=127.0.0.1`,
   private, multicast, documentation и CGNAT-адреса должны быть отклонены.
10. Прервать установку после инициализации SQLite, затем повторить. Данные и ключи
    сохраняются, ожидающие передачи учётные данные доступны.
11. Проверить `systemctl list-timers proxyk-admin-renew.timer`. После успешной выдачи
    выполнить репетицию продления **на тестовой VM**:

    ```bash
    sudo docker run --rm -p 80:80 \
      -v /opt/proxyk-admin/acme:/etc/letsencrypt \
      certbot/certbot:v5.9.0 renew --dry-run --cert-name proxyk-admin
    ```

    `--dry-run` не заменяет проверку фактической автоматической ротации: дождитесь
    окна продления короткого сертификата и сравните serial/NotAfter сертификата,
    полученного внешним TLS-клиентом, без перезапуска Go. Проверьте ошибку timer
    при закрытом порте 80 и последующее восстановление.
12. Повторить установку через выпущенный `curl | sudo bash`, убедиться, что ввод
    читается с терминала. Повреждённый SHA-256 архива должен остановить установку.

## Что не проверяется на этапе 1

- Импорт VLESS URI, реальный VPN-трафик, расход лимитов: этапы 2 и 4.
- Веб-авторизация, cookie, CSRF, rate limiting: этап 3.
- Online backup, restore, обновление с rollback: этап 4.

Пустой REALITY inbound на этапе 1 не выдаёт пользовательских подключений.
Его TLS target `www.cloudflare.com:443` должен быть проверен на конкретном VPS перед
включением пользователей на этапе 2; доступность target зависит от сети сервера.
